# Space Rocks — Clean-Room Gameplay and Visual Design

Status: P7 reference-game design baseline  
Canonical metadata: `src/games/space-rocks/metadata.ts`  
Canonical rule constants: `src/games/space-rocks/design.ts`

## 1. Product identity

**Space Rocks** is an original single-player arcade survival game built around inertial flight, screen wrapping, projectile timing, and progressively denser fields of breakable space debris.

The broad mechanic family is intentionally recognizable as classic wraparound space-shooter gameplay, but the shipped expression is project-authored. Space Rocks does not reproduce commercial cabinet branding, title lettering, exact scoring tables, ship/enemy silhouettes, sound effects, wave tables, or extracted level/ROM data.

### Title treatment

The launcher/title treatment uses a compact two-line `SPACE / ROCKS` wordmark:

- `SPACE` uses a cool cyan treatment;
- `ROCKS` uses a warm gold treatment;
- a short diagonal orbital slash may cross the gap between the two words;
- lettering is solid/block-oriented, not an imitation of a commercial vector-logo treatment;
- launcher art may use the initials `SR` until dedicated project-authored art is added.

## 2. Visual language

The game targets the standard 320x240 logical framebuffer.

### Player craft

The player flies the **Kestrel**, a compact four-point kite-like craft with:

- a broad central diamond body;
- two short lateral fins;
- a small rear notch for the engine plume;
- solid fills with a bright cockpit/core accent;
- a warm exhaust flare while thrusting.

The silhouette must remain visually distinct from a simple triangular outline spacecraft.

### Space rocks

Hazards are **fracture rocks**: solid, irregular faceted mineral masses rather than monochrome outline-only asteroids. Each rock has:

- an asymmetrical 5-8 vertex silhouette generated from project-owned geometry;
- one or more short colored core/crack accents;
- slow deterministic rotation;
- three gameplay sizes: large, medium, and small.

Destroying a large or medium fracture rock creates smaller fragments. Exact child headings and speeds are derived from the shared seeded RNG so tests can reproduce a run.

### Projectiles and effects

The Kestrel fires short **pulse bolts**, rendered as compact luminous capsules/segments. Impact effects use brief geometric shards and dots with hard lifetime/entity bounds. No particle system may grow without a fixed cap.

The background is a sparse dark navy star field with project-generated star positions and subtle brightness variation. No star map or level layout is copied from another game.

## 3. Core run loop

1. A run starts with the Kestrel near the center and a difficulty-dependent set of large fracture rocks placed outside a protected spawn radius.
2. Left/right rotate the craft. Up applies forward thrust; velocity persists when thrust is released.
3. Action 1 fires a bounded pulse bolt in the facing direction.
4. Ship, rocks, and eligible projectiles wrap across all four screen boundaries.
5. Pulse impacts split larger rocks and destroy small rocks.
6. Ship/rock contact costs one reserve hull unless spawn protection is active.
7. Clearing all rocks completes the wave and awards a wave-clear bonus.
8. The next wave increases pressure through the project-owned progression formula and seeded generation.
9. A run ends when no reserve hulls remain. Only then is its score eligible for shared high-score submission.

There are no authored maps or commercial level tables. Wave composition and spawn positions are generated by code from the selected difficulty, wave number, and shared seed.

## 4. Scoring

The initial scoring contract is intentionally independent of familiar commercial scoring tables:

| Event | Points |
| --- | ---: |
| Destroy large fracture rock | 35 |
| Destroy medium fracture rock | 90 |
| Destroy small fracture rock | 225 |
| Clear a wave | `300 + 60 * (wave - 1)` |

A collision does not subtract score. Later balancing may change these values only through an explicit design update and matching tests; game code should import the canonical constants rather than duplicate literals.

## 5. Difficulty profiles

All profiles share the same rules and controls. Difficulty changes pressure, not the fundamental game model.

| ID | Label | Initial large rocks | Rock-speed scale | Spawn protection |
| --- | --- | ---: | ---: | ---: |
| `drift` | Drift | 3 | 0.82x | 2.25 s |
| `orbit` | Orbit | 4 | 1.00x | 1.75 s |
| `nova` | Nova | 5 | 1.18x | 1.25 s |

`orbit` is the default profile. Later wave progression may add rocks and speed within explicit hard caps, but it must preserve deterministic generation for a fixed seed.

## 6. Controls

Space Rocks is playable with keyboard or a standard-mapped gamepad through the shared logical-action system.

| Logical action | Space Rocks behavior |
| --- | --- |
| Left | Rotate counter-clockwise |
| Right | Rotate clockwise |
| Up | Thrust forward |
| Action 1 | Fire pulse bolt |
| Pause | Open shared pause overlay |

No gameplay code reads raw browser key codes or Gamepad API state directly.

## 7. Audio direction

P7-008 will add project-authored audio using the shared audio service. The intended palette is short synthetic/processed effects for thrust, pulse fire, mineral fracture, hull loss, and wave completion. It must not reproduce or sample commercial arcade audio.

## 8. Clean-room/content constraints

For this game specifically:

- no ROM, decompiled code, source code, or extracted data is used;
- no commercial sprites, vector paths, fonts, logos, sound effects, music, or attract-screen text are used;
- no exact commercial score table is used;
- no copied wave/spawn table or level map is used;
- ship and hazard silhouettes are newly authored for this repository;
- deterministic spawn/split behavior is generated from project-owned algorithms and the shared RNG;
- game-specific assets, when introduced, must be project-authored or pass the repository attribution validator.

The initial `assets.json` is deliberately empty because P7-001 defines the visual/gameplay language without importing external assets. P7-008 may add original bundled assets when the effects implementation requires them.
